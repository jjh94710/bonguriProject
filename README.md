# bonguriProject

## 봉우리 물류 분류 자동화 디지털 트윈

컨베이어로 들어오는 택배 상자의 송장 면을 카메라와 학습 모델로 판정하고, 송장면이 위를 향하지 않은 상자는 로봇암이 자세를 교정한 뒤, 송장 번호를 판독해 지역별 터미널 컨테이너에 자동으로 적재하는 물류 분류 셀을 Unity로 구현한 디지털 트윈이다.

| 로봇 | FAIRINO FR5 4대 (교정용 손가락 그리퍼 1대, 적재용 흡착 그리퍼 3대) |
| 상자 | 5 × 6 × 7 cm, 송장 번호 5자리 (지역 코드 2자리 + 일련번호 3자리) |
| 목적지 | 터미널 A 서울(11), B 대전(22), C 부산(33), NG |
| 개발 기간 | 2026-10-27 ~ 2026-11-05 |

## 1. 주요 기능

| 기능 | 설명 | 요구사항 |
| --- | --- | --- |
| 상자 투입 | 정해진 간격으로 상자를 생성하고, 송장면 방향(위 · 측면 · 아래)과 이상 송장 비율을 설정값에 따라 배정한다. | FR-01 |
| 송장 면 판정 | 교정 스테이션의 카메라 5대(위 + 측면 4)로 상자를 촬영하고, 송장 유무 판정 모델(ML ①)이 송장이 붙은 면을 2초 안에 판정한다. | FR-03 |
| 로봇암 자세 교정 | 교정 로봇암이 손가락 그리퍼로 상자를 집어 송장면이 위로 오도록 90°씩 돌린다. 회전 한도는 3회, 제한 시간은 90초다. | FR-05, FR-06 |
| 송장 번호 판독 | 판독 스테이션에서 송장 OCR 모델(ML ②)이 번호 5자리와 지역명을 읽고, 숫자와 주소가 맞는지 규칙으로 검증한다. | FR-04, FR-07 |
| 분류와 적재 | 푸셔가 지역 코드에 맞는 터미널 레인으로 상자를 보내고, 레인 끝의 적재 로봇이 상자를 흡착해 2 × 2 × 2(8칸) 컨테이너에 쌓는다. | FR-08, FR-16 |
| 예외 배출 | 송장 미부착, 판정 · 판독 실패, 규칙 위반, 교정 · 이송 실패 상자를 NG 푸셔가 NG 토트에 모은다. | FR-09 |
| 공정 현황과 경고 | 설비 상태, 처리 수, 시간당 처리량, 예외율, 터미널별 분류 수, 분류 성공 · 실패 수를 화면에 표시하고, 이상 상황은 알람 팝업으로 알린다. 같은 경고가 3번 이어지면 공정을 멈춘다. | FR-10, FR-11 |
| 박스 정보와 시점 전환 | 판독 스테이션에 온 상자의 판독 결과, 목적지, 교정 상태를 보여 주고, 화면 클릭으로 컨베이어 · 푸셔 · 컨테이너 · 로봇팔 시점을 바꾼다. | UI-01 |
| 제어 방식 전환 | 송장 면 판정 방식을 학습 정책(ML ①)과 기본 제어(송장 색 비율 판정) 사이에서 전환한다. | FR-12 |
| 생산 기록 | 상자별 처리 결과와 이상 이벤트를 세션 단위 CSV 파일로 저장한다. | 6장 |

## 2. 공정 흐름

```
상자 투입 → 교정 스테이션 정지 → 송장 면 판정
   ├─ 윗면 ─────────────────────────────┐
   └─ 측면 · 아래면 → 로봇암 자세 교정 → 재판정 ┘
→ 판독 스테이션 정지 → 윗면 재확인 → 송장 번호 판독 → 규칙 검증
   ├─ 정상 → 터미널 A / B / C 분기 → 레인 끝 정지 → 흡착 적재 → 컨테이너
   └─ 예외 → NG 푸셔 → NG 토트
```

![동작흐름표다이어그램](/doc/봉우리_처리흐름도_261104_2.png)

교정 스테이션과 판독 스테이션은 따로 동작하므로, 앞 상자를 판독하는 동안 다음 상자를 교정할 수 있다.

## 5. 설치와 실행

1. Git LFS를 설치한 뒤 저장소를 받는다.

   ```bash
   git lfs install
   git clone https://github.com/jjh94710/bonguriProject.git
   cd bonguriProject
   git lfs pull
   ```

2. Unity Hub에서 Unity 6000.6.0f1로 프로젝트 폴더를 연다. 첫 실행 시 패키지 가져오기에 시간이 걸린다.
3. `Assets/Scenes/bongyuri.unity`를 연다.
4. Play를 누르고 운전 제어 패널에서 **시작**을 누른다.

## 6. 운전과 설정

### 운전 제어 패널

| 조작 | 동작 |
| --- | --- |
| 시작 | 설정한 투입 간격으로 상자를 계속 투입한다. 알람 정지 중에는 누를 수 없다. |
| 사이클 정지 | 새 투입을 멈추고, 처리 중인 상자를 끝까지 처리한 뒤 멈춘다. |
| 알람 해제 | 알람으로 멈춘 공정을 해제한다. 해제한 뒤 **시작**으로 다시 운전한다. |
| 투입 간격 − / + | 1초 단위로 1 ~ 30초 사이에서 바꾼다. 다음 투입부터 적용된다. |
| 기본 제어 / 학습 정책 | 교정 스테이션의 송장 면 판정 방식을 바꾼다. 다음 상자부터 적용되며, 송장 유무 모델이 없으면 학습 정책을 고를 수 없다. |

패널에는 운전 상태, 분류 성공 · 실패 수, 교정 스테이션 대기 시간, 알람 상태, 생산 기록 CSV 경로가 함께 표시된다.

### 화면 구성

| 화면 | 내용 |
| --- | --- |

| 박스 정보 패널 | 판독 스테이션에 도착한 상자의 ID, 송장 판독 결과, 목적지, 교정 상태(회전 횟수), 현재 단계를 색과 함께 보여 준다. |
| 알람 팝업 | 경고가 생기면 종류와 상자 ID를 띄우고 최근 이벤트 5건을 보여 준다. × 는 팝업만 닫는다. |
| 시점 전환 | 첫 컨베이어 화면의 클릭 영역으로 위쪽 · 푸셔 · 컨테이너 A · B · C 시점으로, 컨테이너 시점에서 로봇팔 시점으로 옮긴다. 위쪽 시점에서는 좌우 버튼, 다른 시점에서는 뒤로 버튼을 쓴다. |

### 점검용 메뉴 (Inspector ⋮)

| 컴포넌트 | 메뉴 | 용도 |
| --- | --- | --- |
| `CellController` (BonguriProcess) | 테스트/운전 1개 - Run(1) | 상자 1개만 처리하고 멈춘다. |
| `LoadSequence` (터미널 흡착 로봇) | 테스트/실패 상자 다시 시도, 테스트/컨테이너 비우기 | 적재에 실패한 상자를 다시 집거나 가득 찬 컨테이너를 비운다. |
| `NgTote` (RejectCollectionBox) | 테스트/NG 토트 정리 (Clear) | NG 토트에 쌓인 상자를 지운다. |

### 공정 설정 (`Assets/_Factory/CellSettings.asset`)

| 항목 | 기본값 | 설명 |
| --- | --- | --- |
| 투입 간격 | 10초 | 상자를 투입하는 간격 |
| 송장면 방향 비율 | 위 0.7, 측면 0.05씩, 아래 0.1 | 투입 상자의 송장면 방향 배정 비율 |
| 이상 송장 비율 | 미부착 0, 잘못된 송장 0 | 예외 상황 재현용 비율 |
| 회전 한도 | 3회 | 자세 교정의 최대 회전 횟수 |
| 판독 재시도 한도 | 2회 | "모름" 글자가 남을 때 다시 판독하는 횟수 |
| 지역 코드 표 | 11 서울 → A, 22 대전 → B, 33 부산 → C | 지역 코드와 터미널 대응 |
| 대기 상자 기준 | 5개 초과 시 투입 정지, 2개 이하에서 재개 | 연속 운전 대기열 관리 |
| NG 토트 경고 | 5개 | NG 토트 정리 경고 기준 |

터미널 컨테이너의 자동 비우기는 터미널마다 `LoadSequence`의 **Auto Empty**로 켠다. 끄면 컨테이너가 가득 찼을 때(8칸) 그 터미널이 비울 때까지 기다린다.

### 생산 기록

Play할 때마다 프로젝트 폴더(빌드는 실행 파일 옆)의 `Reports/`에 두 파일을 만든다.

- `boxes_날짜_시각.csv`: 상자별 송장 번호, 판정 면, 회전 횟수, 목적지, 실제 도착 터미널, 예외 사유, 구간별 시간
- `events_날짜_시각.csv`: 이상 이벤트의 발생 시각, 종류, 상자 ID

## 7. 학습 모델

두 모델 모두 지도학습으로 만든 ONNX 파일이며, Unity Inference Engine으로 추론한다. 모델 파일은 `Assets/FactoryMLModels/`에 있다.

| 모델 | 파일 | 입력 → 출력 | 검증 결과 |
| --- | --- | --- | --- |
| ML ① 송장 유무 판정 | `LabelPresence.onnx` | 면 이미지 96 × 96 컬러 → 송장 점수 | 테스트 상자 360개 360/360, 각 면 60/60 |
| ML ② 송장 번호 판독 | `LabelNumber.onnx` | 번호 영역 186 × 32 회색조 → 글자 46칸 × 11종 확률 | 송장 50개 번호 전체 50/50 |
| ML ② 지역명 판독 | `LabelRegion.onnx` | 지역명 칸 96 × 32 회색조 → 지역 3종 확률 | 송장 50개 50/50 |

### 다시 학습하기

1. Unity에서 `Tools > Factory ML > 송장 유무 > 1. 데이터셋 1800상자 생성 준비`로 학습 이미지를 만든다. 판독 모델은 `LabelReaderDataset` 컴포넌트의 **판독 데이터셋 생성** 메뉴로 번호 · 지역 이미지를 만든다.
2. 학습 스크립트를 실행한다.

   ```bash
   conda activate mlagents   # Python 3.10 환경
   pip install -r scripts/requirements-label-presence.txt
   python scripts/train_label_presence.py   # ML ①
   python scripts/train_label_reader.py     # ML ②
   ```

3. 만들어진 ONNX를 `Assets/FactoryMLModels/`에 복사하고, `Tools > Factory ML > 송장 유무 > 2. ONNX 연결 및 360상자 평가 준비`와 `Tools > Factory ML > OCR 판독 및 규칙 검증`으로 평가한다.

학습 데이터 범위, 모델 구조, 평가 방법은 [ML 설계서](#10-문서)에 있다.

## 11. 범위

- 실제 설비, 카메라, 로봇을 제어하지 않는다. 모든 설비는 Unity 안의 가상 설비다.
- ROS2와 연동하지 않으며, 로봇암은 Unity 단독으로 제어한다.
- 상자 크기는 1종, 목적지는 터미널 3곳과 NG다. 설정과 설비 추가로 목적지를 5곳까지 늘릴 수 있다.
- AGV 출하 이동(FR-15)은 이번 버전에서 다루지 않는다.
